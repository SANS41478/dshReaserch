# DeepSeek Harness 全息解构

把 `deepseek-harness`（dsh）整个仓库拆开、摊平、连起来看的一个**离线网站**，
外加一个**能读真实源码的浏览器**。

## 怎么打开

**推荐：双击 `start.bat`**（Windows）或 `./start.sh`（macOS/Linux）。
它会起一个本地服务并自动打开浏览器。有了这个服务，你就能在站内**直接读源码、按行号跳转、全文搜索**。

服务起不来的话，直接双击 `index.html` 也能看——
分层讲解、服务总表、事件矩阵、包清单这些都内嵌在站点里，不需要服务。
只有「源码浏览器」和「读全文」这两个功能需要服务（浏览器不允许网页直接读本地文件）。

> 服务默认端口 `5319`，仓库路径和端口都在 `config.json` 里改。
> 也可以用环境变量覆盖：`DSH_REPO` / `PORT`。

## 左右分屏：一边看讲解，一边读源码

**这是本站读源码的主方式。** 宽屏（≥1240px）下点任意「读源码 / 读全文 / 📍」链接，
源码会开在**右侧常驻面板**里，左侧正在读的讲解**原样不动**——滑动位置、折叠状态全部保留。

```
┌──────────────┬──────────────────────────────────────────────┐
│  左侧导航     │  架构讲解（#content）      │ 源码侧栏（#pane） │
│              │                            │                  │
│  分层深入     │  分层页：能力接缝           │  📄 shell/index.ts│──┐
│  包清单       │  「关键源码」               │  🌲 文件树        │  │ 双页签
│  源码浏览器   │   读全文 →  ────────────┐   │                  │──┘
│  仓库文件树   │  包页：服务角色           │  ┌─ 第 64 行 ─────┐│
│              │   读源码 →              │  │ abstract class  ││
│              │                           │  │ ShellExecutor   ││
│              │                           │  └────────────────┘│
│              │                           │  溯源：ctx.shell → │
└──────────────┴──────────────────────────────────────────────┘
                          ↑ 拖动这个分隔条调整宽度（双击复位）
```

**面板操作**

| 操作 | 说明 |
|---|---|
| 拖动分隔条 | 调整宽度，范围 340px – (视口−420px)；**双击**恢复默认 |
| `⤢` 全屏 | 只看源码，左侧导航与讲解一起让位；`Esc` 或再点一次返回分屏 |
| `✕` / `Esc` | 收起侧栏（标签保留，下次打开还在） |
| 页签 `✕` | 只关这一个标签 |
| 多个标签 | 源码与文件树可以**同时开着**，各自保留滚动位置与定位状态 |

**窄屏（<1240px）**：面板自动降级为覆盖层滑入，`Esc` 或 `✕` 关闭。

## 源码浏览器怎么用

**文件树**（`#/files` 或右栏「🌲 文件树」页签）按「包 → 源码 / 测试 / 文档 / 配置」归类，默认展开源码。

点包页 / 分层页里的 **`📍 在文件树里定位`** 按钮，文件树会：
1. **展开整条路径**的所有祖先目录（`core → tools → src →`）；
2. **滚动**到目标文件并居中；
3. **闪烁高亮**该行，并留下琥珀色底 + 左侧标记条和「📍 已定位 <路径>」提示条，直到你定位下一个。

点任意文件即在右侧面板打开源码，不用切到编辑器。点包目录右侧的 `↗` 可在左侧跳到该包的架构页。

**源码查看器**在右栏面板里是「源码正文 + 底部紧凑溯源条」；
以整页打开（`#/code/...`）时是「源码正文 + 右侧完整溯源面板」。溯源面板回答：

| 面板区块 | 回答的问题 |
|---|---|
| 这个文件 | 我在读哪个文件 |
| 所属包 | 它属于哪个包、什么分组、干什么的（可点击跳到包页） |
| 声明的依赖 | 文件里 `static inject` 声明了哪些服务（可点击跳到服务页） |
| 导出 / 本文件符号 | 导出了什么、每个类和方法各在第几行（**点击直接跳到那一行**） |
| 相关架构概念 | 这个包对应哪些分层讲解页 |
| 同包其它文件 | 横向切到同包的别的源文件 |

**双向溯源**——两条路都能走，且**右栏不会因为左侧换页而关闭**：

```
架构 → 代码：  分层页「关键源码」点「读全文 →」→ 精确落到 agent.ts:296
              包页点「读源码 →」→ 落到该包 src/index.ts
              包页点「📍 在文件树里定位」→ 树里展开并高亮该文件
              服务页点「定义处源码 →」→ 落到服务定义那一行

代码 → 架构：  溯源条点「所属包」→ 包页（左侧切换，右侧分屏保持）
              点 inject 里的服务名 → 服务页（看谁是定义者/提供者/消费者）
              点「相关架构概念」→ 分层讲解页
```

**分享深链**：在 hash 后加 `?pane=1` 可让链接直接以分屏方式打开，例如
`#/code/packages/core/agent-loop/src/agent.ts:296?pane=1`。
不带 `?pane=1` 时 `#/code/...`、`#/files` 仍是整页版，方便单独阅读或截图。

**全文搜索**：服务启动后，`/api/search?q=关键词` 会 grep 整个源码仓库并返回文件+行号
（站内搜索框目前仍只搜架构索引，源码 grep 走 API）。

## 可点击溯源

站内**每一个**包名、服务名、工具名、事件名都是链接。典型链路：

```
分层「能力接缝」→ 点 ctx.shell → 看到 定义=shell / 提供者=bash-local,bash-sandbox,pwsh-local
                → 点 bash-local → 看到它依赖谁、谁依赖它 → 继续点下去
                → 点「读源码」→ 直接看 bash-local 的实现，右侧面板显示它 inject 了 subprocess
```

## 服务端接口

| 接口 | 作用 |
|---|---|
| `GET /api/meta` | 仓库路径 + 完整文件树 |
| `GET /api/tree` | 只取文件树（4 秒缓存） |
| `GET /api/file?path=` | 读单个文件全文 |
| `GET /api/trace?path=` | 溯源：所属包、inject、导出、符号、同包文件 |
| `GET /api/symbols-for?path=` | 单文件的符号表（类/方法/函数 + 行号） |
| `GET /api/symbols` | 全局符号索引 |
| `GET /api/search?q=` | 源码全文 grep，返回文件:行号 |

服务**实时读磁盘**，你在编辑器里改完保存，网页刷新即最新（文件树有 4 秒缓存，其余无缓存）。

## 关于准确性

- 「包清单 / 服务 / 工具 / 事件 / 配置行」是**脚本从仓库真实文件里抽的**，不是手写。
- **逐包精读（265/265 全覆盖）**：每个包页的「为什么必须有它 / 系统位置 / 内部结构 / 职责边界 / 源码带读 / 坑 / 通俗复述」是**人写的深度解读**，
  由多个阅读代理基于 `data/deep/brief/` 的符号索引 + 实际打开源码写成，
  其中 1276 条「源码带读」的行号逐条打开文件核对过。它们是解释，不是规范；权威定义仍在仓库 `docs/`。
  已知的数据快照问题（写在对应包页的「坑」里）：`code-runtime` 两包、`settings-file`、`agent-presets`、e2b 三包在本地快照只有编译产物没有 `src/`；
  `workflow-worker-thread` 已在上游最新提交中删除（解读基于 git 历史）。
- 源码浏览器的文件内容、行号、符号、inject 声明，都是**从磁盘现读现扫**的。
- 符号索引是**正则扫描**建的（约 2900 个源文件 / 1.8 万个符号），不是真正的 TypeScript 语言服务。
  它能准确抓出类、方法、函数、接口、`static inject`、`declare module`，
  但**不做类型推断、不做跨文件引用解析**。要精确的跳转定义，仍需编辑器或 `tsserver`。
- 「18 层叙述、机制表、通俗复述」是**人写的解释**，基于对源码的阅读；它们是导航，不是规范。
- 权威定义永远在仓库自带的 `docs/`（本站在 `#/about` 里列了主要来源）。
- 仓库是 pre-stable，API 会变；架构快照对应抽取时的那个状态，源码则永远是最新的。
